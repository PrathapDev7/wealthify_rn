# iOS Widget Extension — one-time Xcode setup

The SwiftUI sources are committed (`ios/AlignWidgets/AlignWidgets.swift` +
`AlignWidgets.entitlements`). Xcode project wiring cannot be generated by
scripts, so do this once in Xcode:

## 1. Create the Widget Extension target

1. Open `ios/Runner.xcworkspace` in Xcode.
2. File → New → Target → **Widget Extension**, name it `AlignWidgets`.
3. When Xcode asks about the scheme, keep it.
4. Delete the template `.swift` files Xcode generates inside the new target —
   the committed `ios/AlignWidgets/AlignWidgets.swift` is the implementation.
5. Add the committed file to the target: drag `ios/AlignWidgets/AlignWidgets.swift`
   into the `AlignWidgets` group if it isn't already a member.

## 2. Match the identifiers

- Widget Extension bundle id: `com.invent.wealthify.AlignWidgets`
- Version + build must track the Runner target (Xcode usually keeps `$(FLUTTER_BUILD_NAME)`
  / `$(FLUTTER_BUILD_NUMBER)` — keep it that way).
- Deployment target: iOS 14.0 minimum (the code uses only iOS 14 APIs).

## 3. App Groups (both targets)

1. Select the **Runner** target → Signing & Capabilities → **+ Capability** →
   **App Groups** → check `group.com.invent.wealthify`.
2. Repeat for the **AlignWidgets** target with the same group.
3. The committed entitlements files already declare the group:
   - `ios/Runner/Runner.entitlements`
   - `ios/AlignWidgets/AlignWidgets.entitlements`

   If Xcode doesn't pick them up, set each target's
   **Code Signing Entitlements** build setting to its file.

## 4. URL scheme (widget taps)

`ios/Runner/Info.plist` already declares the `align://` scheme
(`CFBundleURLTypes` → `com.invent.wealthify.widget`). Widget taps open
`align://widget?homeWidget=<screen>`, which the Flutter side routes via
`AppLinks.routeForWidgetUri`.

No further Xcode step needed — just don't delete that plist entry.

## 5. Shortcuts (no setup)

Long-press quick actions are registered at runtime by the `quick_actions`
plugin (`QuickActionsSetup`), so there is nothing to configure in Xcode.
Icons: iOS maps `ShortcutItem.icon` to a template image name; the dynamic
items work with or without matching asset names, and currently use the
shared `ic_shortcut_*` names (asset catalog images can be added later if
you want custom glyphs instead of the system default).
